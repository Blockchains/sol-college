Portfolio track · Wave 1 · verified 2026-11-22

Nosana GPU job market (browser app + campus worker)

Nosana's open-source job, staking and rewards programs deployed as independent lab programs on Solana devnet with a practice NOS token, plus a modified version of the Nosana dashboard. Connect a devnet wallet, post a container job from the browser, and watch the campus worker claim it, run it with Nosana's own executor and post a verified result on-chain. Failed jobs are diagnosed from the result.

Devnet practice lab, not the official product. Lab programs 4nFPjT5M… (jobs), qqA8dv9j… (staking) and EWdwdb7J… (rewards) with a practice NOS mint GKkroxnq… that has no value. This is not the Nosana network and is not run or endorsed by Nosana. The official node daemon (nosana-node start) does not run here because it needs Nosana's private host-manager, FRP tunnel server and a GPU benchmark; a campus worker built from @nosana/kit and Nosana's executor (nosana-node run) serves the browser market instead.

Source code of the app (GPL-3.0)

The browser app is a modified version of nosana-ci/nosana-dashboard (© Nosana, GPL-3.0). Its complete source, including the build script, is published at Blockchains/nosana-dashboard, branch sol-college-devnet; the hosted build is commit 8452a40. What changed and what is stubbed: NOTICE and SOL-COLLEGE.md. You may copy, modify and redistribute it under the GNU GPL v3; it comes with no warranty.

Stubbed in the app: Nosana dashboard API (templates, deployments, credits, vault, logs), SuperTokens accounts and OAuth, Stripe and crypto top-ups, Pinata IPFS (replaced by allow-listed templates and memos whose CIDv0 hashes are checked against the chain), node log streaming over FRP, analytics and the service worker. Only three allow-listed job templates run (deterministic hash, hash your own text, fail on purpose); anything else is refused, never executed.

Rejected as expected

  • work by a wallet with no stake account is rejected (AccountNotInitialized)
  • finish by a wallet that is not the assigned node is rejected (Unauthorized)
  • finish a completed job again is rejected (kit guard: the run account was closed by finish) (No job run account found)
  • finish replayed on-chain against the closed run account is rejected (AccountNotInitialized)
  • recover by a wallet that did not post the job is rejected (Unauthorized)
  • Browser market: a job whose definition is not an allow-listed template (no matching memo) is finished as refused and never executed.
  • Browser app: a tampered memo cannot change a result, because the page only shows a result whose CIDv0 equals the ipfsResult written on-chain by the node.

Open blockers

  • nosana-node start depends on Nosana's private host-manager (registration, market request, benchmark, heartbeat) and FRP server; there is no public implementation. A standalone mode or published host-manager would be needed for the real node daemon.
  • Campus worker uptime: the worker runs on the Sol.College lab machine under a keepalive loop. If that machine restarts, posted jobs stay Queued until campus-keepalive.sh is started again.
  • Licences: nosana-kit and nosana-node have no LICENSE file upstream; the Sol.College owner approved using them in this track on 2026-11-22. The dashboard is GPL-3.0, so the modified app's full source is published (see above).
  • No named campus owner for this track yet.

Reset

Every lifecycle run starts with a soft reset: delist queued jobs, take the node out of the node queue and recover the deposits of stopped jobs. Full reset: new program, mint and authority keys, patch common/src/id.rs, rebuild, deploy, run init.mjs, and close the old programs to reclaim SOL. See the lab README.

Improvement backlog

  • @nosana/kit 2.24.5 stake() ignores the configured staking program id, so it always targets mainnet staking; the lab calls the generated client directly.
  • kit and its generated jobs client have no recover instruction; the lab builds it from the Anchor discriminator.
  • kit errors hide the program logs (they are in e.details.context.logs).
  • nosana-node's network option defaults to mainnet; a devnet-first default would be safer for teaching.
  • A browser front end for the lab (post job, watch status, read logs) against the lab programs.
  • Run the upstream Anchor test suite on a local validator.
