Squads V4 multisig treasury

Squads V4, the Solana multisig, deployed as an independent lab program on devnet with its own public client. Create a multisig, add members, set a threshold, fund the vault, propose, approve, execute and inspect history.

Devnet practice lab, not the official product. This is an independent deployment of the open-source Squads V4 program (program TZNQuhC8PSqQY7Szj9RJsMQirVooYSahh396QNqTMGU) with freshly generated authorities. It is not the official Squads program (SQDS4ep6…) and is not run or endorsed by Squads. Always fund the vault address, never the multisig account.

Rejected as expected

  • program_config_init by a key other than the lab initializer: rejected (Unauthorized).
  • vault_transaction_create by a non-member: rejected (NotAMember).
  • proposal_approve by a non-member: rejected (NotAMember).
  • vault_transaction_execute with 1 of 2 approvals: rejected (InvalidProposalStatus).
  • proposal_approve twice by the same member: rejected (AlreadyApproved).
  • vault_transaction_execute by a non-member after approval: rejected (NotAMember).
  • vault_transaction_execute a second time: rejected (InvalidProposalStatus).
  • Execute after the proposal was rejected by 2 members: rejected (InvalidProposalStatus).
  • Execute after an approved proposal was cancelled by 2 members: rejected (InvalidProposalStatus); vault unchanged.
  • UI: an outsider wallet sees Send SOL disabled.
  • UI: executing a 0.067 SOL transfer from a 0.015 SOL vault failed on-chain (5bYiCWhx…, insufficient lamports); nothing moved until the vault was topped up.

Open blockers

  • No named campus owner (Maintain gate).
  • Upstream Anchor test suite not yet run on the box (needs a local validator run, one at a time to stay within RAM).

Reset

Run sol-college/squads-v4.mjs again: each run uses a new random createKey, so it creates a new empty multisig. The program config is shared and initialised once. In the app, use Create to make your own multisig with your devnet wallet.

Improvement backlog

  • SDK: rpc.proposalCreate in @sqds/multisig 2.1.4 ignores its rentPayer argument and always charges the creator.
  • SDK: system-program errors are translated to an unrelated error name (a failed rent transfer surfaced as TokenLendingError#AlreadyInitialized).
  • Client: Send Tokens still computes amounts with floating point (parsedAmount * 10 ** decimals); the SOL path is fixed in the lab fork.
  • Client: sends with skipPreflight, so a member with too little SOL for rent, or an under-funded vault, only sees 'Transaction failed or timed out'; decode the on-chain error instead.
  • Client: warn before execute when the vault balance is below the proposed transfer.
  • Client: approval progress (n of threshold) and a proposal search on the Transactions page.
